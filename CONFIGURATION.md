# Credentials and runtime configuration

There are two profiles. Development can use the limited rules parser and explicit stub backend without
provider accounts. The full production profile requires Claude, a real authenticated managed-search/verifier
backend, supplier mappings, and an HTTPS public origin. A passing configuration check means the settings are
present and structurally acceptable; it does **not** prove provider access, backend compatibility, product
suitability, formal-proof correctness, or deployment readiness.

For the local presentation, the [demo guide](docs/DEMO.md) adds an explicit `--demo` MS factory
with fictional catalog evidence. It can use Claude parsing and does not require a live search backend.

## Create private settings

Run from this checkout with the same Python environment that has both requirements files installed:

```powershell
python scripts/configure.py init
python scripts/configure.py check
# Separate full-flow profile; this intentionally reports missing external inputs initially.
python scripts/configure.py init --profile production --env-file .env.production
python scripts/configure.py check --env-file .env.production
```

`init` creates two independent cryptographically random application secrets without printing them. It refuses
to overwrite an existing file: changing the shared signing secret invalidates existing signatures and request
capabilities. `.env.local`, `.env.production`, and `secrets/` are ignored by Git. On Linux new files have mode
0600; on Windows they inherit the destination directory's ACL, so keep the checkout in your private user directory.
Ignored files still need private filesystem permissions and backups. Do not put keys in demo JavaScript or commit them.

The reader accepts literal `KEY=value` lines and optional surrounding single/double quotes. It never evaluates
shell code or expands `$VARIABLE` references. Use one-line JSON for supplier mappings. File values override
inherited environment variables, including blank values; this prevents an unrelated inherited key hiding an
incomplete setup. Secret-manager-injected variables can instead be omitted from the file.

## Required inputs

| Setting / credential | Where it comes from | Who uses it |
|---|---|---|
| `PROXY_SHARED_SECRET` | Generated by `init`; configure the same value in proxy, MS, and any verifier that validates these signed handoffs | Server processes only |
| `PROXY_API_TOKEN` | Separately generated by `init`; operator audit API credential | Proxy and trusted operator tooling only |
| `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` | Your Anthropic project/account | MS only |
| `ANTHROPIC_MODEL` | Explicit model ID available to that Anthropic account; template retains `claude-opus-5-5` | MS |
| `ENGINE_URL` | Actual deployment of the separate managed-search/formal-verifier service | MS |
| `VP_AGENT_KEY` (alias `ENGINE_AGENT_KEY`) | Credential issued/configured by that verifier, not a random key invented only in PAPR | MS; sent as bearer authentication |
| `ENGINE_API_KEY` | For the alternative legacy `ENGINE_KIND=http` adapter | MS; sent as bearer authentication |
| `PROXY_PUBLIC_URL` | Your stable HTTPS hostname, without a path | Proxy's OAuth issuer/resource metadata and browser login |
| Exact OAuth callback and client ID | Callback supplied by the agent, registered with `proxy.manage_accounts client` | Agent connector and proxy registry |
| `MS_SUPPLIER_HOSTS` | Operator mapping of exact supplier hostnames to IDs in company policy | MS |
| `PROXY_VAR_DIR`, `MS_DATABASE` | Absolute persistent storage paths on the deployed host | Proxy, MS, and backups |
| Cloudflare Tunnel credentials | Your Cloudflare tunnel, if that ingress is chosen | `cloudflared`, separately from application settings |

SQLite needs no cloud database key. This public OAuth client uses PKCE and no client secret. Account passwords
are provisioned through the hidden CLI prompt, not `.env`. External search, browser, payment, or solver provider
keys belong to the external verifier; its implementation/configuration must be available before we can enumerate
or validate those credentials. There is no payment connector or enterprise identity-provider federation in this repo.

For the Anthropic key:

1. Sign in at [Claude Platform](https://platform.claude.com), open **Settings → API keys**, and choose **Create key**.
   Use a normal inference API key, not an Admin API key. Add provider billing/credits if the account requires it.
2. Open the generated `.env.production` in your local editor. Paste the value after `ANTHROPIC_API_KEY=` and save.
   Do not paste the secret into chat or a source file. If you use `ANTHROPIC_AUTH_TOKEN` instead, remove the blank
   API-key entry and configure the token through your secret manager/file.
3. Run `python scripts/configure.py check --env-file .env.production`; it reports only whether the credential is set.
   Authentication/model access still needs an explicit live smoke test after the services are configured.

These steps follow the provider's [API key guide](https://platform.claude.com/docs/en/get-api-key).
You do not need to know a verifier URL yet: it is the address of the separate verifier **after it is deployed**.
Likewise, choose `PROXY_PUBLIC_URL` when the HTTPS hostname/tunnel is provisioned. Neither value can be generated
as a working external service by filling in a placeholder, and neither is an additional AI API key.

Example supplier mapping shape: `MS_SUPPLIER_HOSTS={"www.actual-supplier.com":"sup_01"}`. Replace the hostname
and ID with the real supplier and the same approved-supplier ID used by the account's company policy. Supplying
a map does not establish that a seller is trustworthy or that it publishes usable structured listing evidence.

## Start the pair

Use two terminals; each launcher validates settings before binding a service and runs one worker on loopback:

```powershell
python scripts/configure.py run --env-file .env.local --service main-service
python scripts/configure.py run --env-file .env.local --service proxy
```

Use `.env.production` for the full profile. Proxy binds 127.0.0.1:8000, MS 127.0.0.1:8001, and an external
verifier on this same machine must use another port, such as 8002. Expose only the proxy through your HTTPS
ingress and preserve its public Host header. NixOS/systemd can inject these values from a private EnvironmentFile
and run the same Uvicorn modules with `PAPR_ENV=production`; its service definition, TLS/tunnel provisioning,
backup/restore, and uptime checks still need deployment work. Both processes must share the signing secret.
The launcher removes AI/verifier credentials from the proxy environment and the audit credential from MS.
When using systemd directly, use separate per-service environment files with only that process's credentials.

`PAPR_ENV=production` additionally activates startup guards in both services even when launched directly.
It rejects missing primary credentials, the stub backend, legacy caller-supplied profiles, and automatic rule
fallback. The full preflight also validates loopback-only MS placement, non-embedded credentials in URLs,
supervised backend mode, and persistent paths. Use it before each deployment, rather than treating startup alone
as complete validation. It performs no network calls and prints only credential presence, never their values.

If Claude fails in production, the request records processing failure instead of silently weakening parsing.
Development retains the existing rules fallback unless `SPEC_ALLOW_RULE_FALLBACK=0`. The parser now uses the
stable [`client.messages.parse()` structured-output API](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
with an explicitly selectable model; no hardcoded beta headers or server-side fallback option are required.
See [Anthropic's model catalog](https://platform.claude.com/docs/en/models/overview) for account/platform availability.

After configuring inputs, provision company/users and register the exact callback using
[ACCOUNTS.md](proxy/ACCOUNTS.md). Keep the account CLI pointed at the same `PROXY_VAR_DIR`, or pass its explicit
`--database` path. Then smoke-test HTTPS browser login, OAuth/PKCE + MCP, a representative Claude parse,
the managed backend, and independent listing checks. A live inference test consumes provider credits.
Optimality and purchase execution are outside this configuration work.
